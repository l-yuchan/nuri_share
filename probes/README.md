# 데이터셋 품질 프로브

모델 성능(66~69%)이 낮은 이유가 **표현력 부족**인지 **데이터셋 자체**인지 분리하기 위한
두 개의 판단 테스트입니다. 두 테스트 모두 정답 라벨을 숨긴 채로 판단하게 하고,
나중에 `analyze_probes.py`로 골드 라벨과 비교합니다.

```
probes/
  README.md              # 이 문서
  llm/                   # 테스트 1: 웹 LLM 배치 프롬프트 (batch_01~04.md)
  human_probe.html       # 테스트 2: 사람이 직접 분류하는 페이지
  manifest.json          # 검증 158행의 모델 예측·선택 규칙 (채점용, 수정 금지)
```

## 테스트 1 — LLM 판단

`probes/llm/batch_01.md` ~ `batch_04.md`가 각각 독립된 프롬프트입니다.
파일 전체를 복사해 **새 대화**에 붙여넣고, 출력 전체를 저장하세요.
자세한 절차와 주의는 [llm/README.md](llm/README.md)를 보세요.

- 검증 158행 전체, 40행씩 4배치. 순서는 고정 시드로 섞여 있어 라벨이 몰려 있지 않습니다.
- 각 행마다 5개 영역에 1~5점을 매기고 1순위와 사유를 출력합니다.
  → 정확도·top-2뿐 아니라 **골드 라벨이 몇 점을 받았는지**를 볼 수 있습니다.
- 골드 라벨 점수가 2 이하인데 다른 영역이 4 이상이면 "라벨 오류 의심" 후보입니다.
- 같은 배치를 두 번, 가능하면 서로 다른 모델 2~3개로 실행하면
  모델 간 합의도(사람이 도달할 수 있는 상한의 추정)를 볼 수 있습니다.

## 테스트 2 — 사람 판단

`probes/human_probe.html`을 브라우저로 열면 바로 시작합니다(설치·서버 불필요, 오프라인 동작).

- 56문항: 모델이 틀렸거나 마진이 낮은 **어려운 항목 40개** + 모델이 확신한 **대조 항목 16개**.
- 대조 항목은 "사람도 틀리는 항목"과 "데이터가 이상한 항목"을 구분하기 위한 기준선입니다.
- 키보드: `1`~`5` 1순위, 이어서 `1`~`5` 2순위(선택, `Enter`로 생략), `6` 판단 어려움,
  `h` 맥락 힌트, `←` 이전 문항.
- 진행 상황은 브라우저에 자동 저장됩니다. 중간에 닫아도 이어서 할 수 있습니다.
- 끝나면 "결과 보기"로 정답을 확인하고, 라벨이 잘못됐다고 판단되는 항목을 체크합니다.
- **CSV 내려받기**로 `human_probe_results.csv`를 저장해 주세요.

## 채점

```sh
# 모델별 폴더를 넘기고, batch_<n>_<run> 파일을 모델·실행 단위로 합칩니다
uv run python analyze_probes.py \
  --llm probes/llm/results/gpt \
  --llm probes/llm/results/gemini \
  --merge-batches \
  --human probes/human_probe_results.csv
```

`--llm`은 반복해서 넘길 수 있습니다. `--merge-batches` 없이 폴더를 넘기면 파일 하나가
판단 하나로 채점되어 배치별 정확도만 나옵니다. 결과는 `probes/analysis.md`(읽기용)와
`probes/analysis.json`(기계용)에 기록됩니다.

## 결과 해석

| 관찰 | 해석 |
|---|---|
| LLM·사람 정확도가 85~90% | 라벨은 재현 가능. 모델 66%는 표현/학습의 한계이지 데이터 오류가 아님 |
| LLM·사람 정확도 70~80%, 골드 점수는 대체로 4~5 | 라벨은 방어 가능하지만 장면이 여러 영역에 걸침 → top-2를 주 지표로 |
| 골드 점수 1~2가 20% 이상 | 라벨 오류 또는 정의 불일치 후보 → 의심 목록을 개별 검토 |
| 어려운 항목 정확도가 대조 항목과 비슷 | 모델이 틀린 곳이 실제로 어려운 곳이 아님 → 라벨 노이즈 의심 |
| 사람과 LLM은 서로 일치하는데 골드와 불일치 | 가장 강한 라벨 오류 증거 |
| 힌트 사용 시 정확도 상승 | 맥락 정보 부족이 원인 → 입력에 맥락을 넣는 방향 |

## 설계 노트

- **입력은 `text`만** 씁니다. 모델 실험과 같은 조건이라야 "데이터 문제"와 "모델 문제"가 분리됩니다.
  `item_text`, `content_category`, `label_source`는 라벨에서 파생된 값이라 제외했습니다.
- **`group_id`를 노출하지 않습니다.** KICCE 그룹 ID(`KI-1-…` ~ `KI-5-…`)의 첫 숫자가
  영역 번호와 일치해 정답을 알려주기 때문입니다. 힌트에는 `context`와 `age`만 씁니다.
- **블라인드**입니다. 정답은 HTML에 base64로만 들어 있고 판단이 끝난 뒤에 공개됩니다.
- 검증 158행은 사실상 **13개 그룹**(KICCE 11 + 사례집 2)이라 행 단위 정확도는 과대평가됩니다.
  그래서 채점표에 그룹 평균 정확도를 함께 넣었습니다.
- 골드 라벨은 교사(사례집)와 척도 개발자(KICCE)가 붙인 단일 라벨입니다.
  이 프로브는 그 라벨의 재현 가능성을 재는 것이지, 절대적 정답을 재는 것이 아닙니다.
